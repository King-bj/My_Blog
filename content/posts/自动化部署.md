# 多环境自动化部署的一次收敛

## 背景（Situation）

多套环境（开发/测试/预发/生产）部署逻辑分散且各自演化，新人很难一次性跑通。每次新增环境都需要找多个人确认步骤。

## 目标（Task）

收敛到一份统一的部署脚本，环境差异用变量驱动，任何人按文档都能独立完成部署。

## 行动（Action）

### 以容器化 MongoDB 初始化为例

环境变量驱动差异（密码、数据路径按环境变量传入）：

```shell
# 启动 MongoDB 容器
docker run -d \
  -p 27017:27017 \
  --name mongodb \
  -e MONGO_INITDB_ROOT_USERNAME=admin \
  -e MONGO_INITDB_ROOT_PASSWORD="${MONGO_PASSWORD}" \
  -v "${DATA_PATH}/mongodb/data:/data/db" \
  mongo:4.4.3
```

### 初始化数据

```shell
# 解压初始化数据包
tar -zxvf init-data.tar.gz

# 复制到容器内
docker cp init-data <mongo-container-id>:/init-data/

# 进入容器执行导入
docker exec -it <mongo-container-id> mongorestore \
  --db your_db_name \
  --authenticationDatabase admin \
  --username admin \
  --password "${MONGO_PASSWORD}" \
  /init-data/
```

### 统一部署脚本结构

```
deploy/
├── deploy.sh          # 主入口，读取环境变量
├── envs/
│   ├── dev.env        # 开发环境变量
│   ├── test.env       # 测试环境变量
│   └── prod.env       # 生产环境变量（不提交到 git，用 CI 注入）
├── services/
│   ├── mongodb.sh     # MongoDB 部署逻辑
│   ├── redis.sh       # Redis 部署逻辑
│   └── app.sh         # 应用部署逻辑
└── README.md
```

调用方式：

```shell
ENV=test bash deploy.sh
ENV=prod bash deploy.sh
```

### 关键设计原则

1. **密码不进代码仓库**：通过环境变量或 CI 密钥注入，`prod.env` 不提交 git
2. **幂等性**：每个步骤先检查是否已存在再创建，支持重复执行
3. **回滚友好**：旧容器停止前先保留，确认新容器健康后再删除

## 收获（Result）

新环境从零到部署完成的时间从 1 天缩短到 1 小时，部署文档只需维护一份，故障时任何人都能独立完成 rollback。
