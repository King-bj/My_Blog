# DEMO 环境 Linux Cache 占用居高不下问题分析

## 背景（Situation）

客户的 DEMO 环境运行一段时间后内存 cache 持续上升，引发用户疑虑。

## 目标（Task）

给客户一个有数据支撑的解释，并判断是否需要修复。

## 行动（Action）

说明：2023年7月4日开始关注缓存占用问题
- 5日0点后，cache开始增加
- 5日0点10分后，cache迅速增长
- 5日18点暂停监控，清理cache
- 6日0点，cache暂未变化
- 6日9点，cache变化不大
- 6日9点30分，启动监控服务
- 6日10点，cache增长
- 7日0点，cache开始迅速增长
- 7日0点10分，cache达到44G

问题总结
通过对操作系统buff/cache缓存内容深入分析，以及对监控易系统的停服排查，基本可以确定缓存占用内存超高是由于监控易系统数据库文件缓存导致的，鉴于该服务器中同样部署了Mysql、ElasticSearch、Nebula等对系统磁盘IO占用较高的服务，系统运行过程中出现资源争用的情况不可避免，在服务急需内存的场景下，由于内存被缓存占用，没有得到及时释放，很有可能导致服务的不稳定，建议将监控易服务单独部署或者采取措施，降低内存占用，为服务器运行保留足够的空闲内存

## 收获（Result）

证明这是 Linux 页缓存的正常行为，不影响业务；同步沉淀了一份对外解释材料。
