# 少而准：监控告警实践与分级

## 背景（Situation）

早期告警没有分级，运维一晚上能收到几百条消息，关键问题反而被淹没。告警既有 CPU 使用率 70% 这种低危信息，也有服务完全不可用这种紧急故障，全都以同样的方式发出。

## 目标（Task）

重新设计一套「少而准」的告警策略，让真问题第一时间发出，噪音降到最低。

## 行动（Action）

### 1. 告警分级（P0–P3）

| 级别 | 定义 | 通知方式 | 示例 |
|------|------|---------|------|
| P0 | 直接影响用户，服务不可用 | 电话 + 即时消息（5 分钟内响应） | 错误率 > 5%，服务无响应 |
| P1 | 用户感知边界，接近 SLO 阈值 | 即时消息（30 分钟内响应） | 错误率 > 1%，P99 延迟 > 2s |
| P2 | 资源风险，尚未影响用户 | 工单（工作时间处理） | 磁盘使用率 > 85% |
| P3 | 趋势预警 | 日报或工单 | 磁盘 7 天内预计满 |

原则：**只有这个指标直接指向了明确的问题，才发告警。**

### 2. 使用 VictoriaMetrics + vmalert 实现秒级触发

监控采集间隔 2s，告警触发延迟 3s 内。vmalert 规则示例：

```yaml
groups:
  - name: service.rules
    interval: 2s           # 评估间隔
    rules:
      # P0：错误率超过 5%
      - alert: HighErrorRate_P0
        expr: |
          sum(rate(http_requests_total{status=~"5.."}[1m]))
            /
          sum(rate(http_requests_total[1m])) > 0.05
        for: 3s            # 持续 3s 才触发，避免毛刺
        labels:
          severity: P0
        annotations:
          summary: "服务错误率超过 5%：{{ $value | humanizePercentage }}"
          runbook: "https://wiki.example.com/runbooks/high-error-rate"

      # P2：磁盘使用率超过 85%
      - alert: DiskUsageHigh_P2
        expr: |
          1 - (node_filesystem_avail_bytes{mountpoint="/"}
               / node_filesystem_size_bytes{mountpoint="/"}) > 0.85
        for: 5m
        labels:
          severity: P2
        annotations:
          summary: "磁盘使用率 {{ $value | humanizePercentage }}，节点：{{ $labels.instance }}"
```

### 3. 同质告警合并与沉默窗口

在 Alertmanager 中配置：

```yaml
route:
  group_by: ['alertname', 'cluster']
  group_wait: 30s          # 等待同组告警聚合
  group_interval: 5m       # 同组后续通知间隔
  repeat_interval: 4h      # 告警持续时不重复通知的时间

inhibit_rules:
  # P0 触发时，抑制同服务的 P1/P2
  - source_match:
      severity: P0
    target_match_re:
      severity: P[12]
    equal: ['service']
```

### 4. 告警通报模板（P0 首报）

```
故障模块：<模块名称>
故障等级：P0
影响范围：<受影响的用户/功能>
故障时间：<发现时间>
预计恢复：<预估时间>
当前状态：正在排查中
```

恢复或 2 小时节点发送进展通报；故障恢复后输出 postmortem 报告。

## 收获（Result）

按 P0–P3 分级 + 同质告警合并 + 沉默窗口后，单日告警量下降 80%，关键事件平均响应时间从 20 分钟降到 5 分钟。on-call 工程师夜间收到的 P0 告警准确率从 60% 提升到 92%。
