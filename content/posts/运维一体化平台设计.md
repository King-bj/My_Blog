# 运维一体化平台设计：从一堆脚本到统一入口

## 背景（Situation）

生产环境涉及上百个微服务，没有完善的可观测体系问题定位就只能靠肉眼看日志，效率极低。

## 目标（Task）

我主导监控与日志体系的设计与落地，目标是让任何线上问题都能在分钟级被发现并定位。

## 行动（Action）

### 背景

运维一体化平台是为了解决用户系统多，维护困难现状，而从多个角度进行监控，检测，发现问题，定位问题，预警问题，记录问题而完成的一站式解决方案。

### 功能

apm，智能日志，统一告警，电子工单，模型管理，拨测，压测，知识库，可视化，应用画像，基础服务。

### 技术栈

SpringBoot  基础框架

SpringBoot Gateway 网关

Feign 服务调用

[MyBatis-Plus](https://baomidou.com/) 数据库操作

Nacos 配置中心

Mysql 结构数据存储

ElasticSearch 采集/告警数据存储

Flume agent采集

Redis 缓存

Kafk 消息队列

Spark 日志解析

Docker 镜像管理

### 职责

在整体产品中，主要负责智能日志模块整体架构的设计规划开发以及整体产品线的研发方案设计评估，基于智能日志原始版本进行了架构升级改造。完成了java服务升级为spring cloud微服务架构，支持容器化部署，中间件版本升级适配等工作。

- 管理工作
  - 负责整体产品开发进度的跟进
  - 负责需求设计确认及开发方案评估
- 性能优化
  - 基于spark + drools进行数据分析，修改原spark任务为flink任务，并优化原有代码逻辑，由资源占用1c1g的spark任务每秒处理日志数约为300条/s 优化为10000条/s，并可以根据资源数进行kafka->es的多种组合式扩容
  - 使用 Arthas 监控spark任务，分析处理速度慢的方法，使用jprofile监控大的内存对象，优化减少内存占用以及提高处理效率。
- 功能开发
  - 基于ssh，实现了agent的远程安装及配置下发
  - 基于k8s，实现了agent的远程监控和远程配置读取
  - 基于flume，实现各类源日志的采集
  - 基于drools，根据页面配置数据规则，自动生成drools脚本,实现动态清洗日志数据
  - 基于开源大模型chatglm/通义千问，实现日志的语义分析功能
- 产品适配
  - 基于flume，在原有采集方案上修改k8s容器的采集方案，基于sidecar方式部署agent,不侵入其它系统采集
  - 适配容器化环境，支持k8s安装，支持arm64和x86类型的服务器
  - 基于 mybatis-plus, 兼容mysql,db,kingbase
  - 基于bboss框架，es兼容es7,8,opensearch。升级后架构支持日均采集200G日志，总日志保留半年稳定运行半年基本无异常。
