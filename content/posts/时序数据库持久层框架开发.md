# 时序数据库持久层框架开发：让业务只关心读写

## 背景（Situation）

项目里多个模块都要写时序数据（监控指标、APM、业务事件），各自接 Lindorm 的代码重复且难统一。

## 目标（Task）

抽象一层时序数据库持久层框架，让业务方只关心"写什么、查什么"，把建表 / Schema / 重连等细节屏蔽掉。

## 行动（Action）

### 设计目标

1. **零样板代码**：业务用注解声明实体，自动建表 / 序列化。
2. **可观测**：内置写入耗时、慢查询、连接池指标。
3. **可替换**：抽象出 `TsdbClient` 接口，底层 Lindorm / TDengine / InfluxDB 可切换。

### 核心抽象

```java
@TsdbTable(name = "metric")
public class Metric {
    @TsdbTag    private String host;
    @TsdbTag    private String service;
    @TsdbField  private double cpu;
    @TsdbField  private double memory;
    @TsdbTime   private long ts;
}

public interface TsdbRepository<T> {
    void save(T entity);
    void saveBatch(List<T> entities);
    List<T> query(TsdbQuery query);
}
```

### 关键实现点

- **元数据扫描**：启动时反射读取 `@TsdbTable`，自动生成建表语句并与远端 schema 对比。
- **写入缓冲**：批量写 + 触发器（满 N 条或满 T 毫秒），单条 API 转为批量。
- **连接重连**：使用心跳 + 指数退避，重连期间写入暂存到 RingBuffer，恢复后回放。
- **降级开关**：远端不可用时切到本地落盘，恢复后异步回灌。

### 框架封装层次

```
业务层  ────  Metric / TraceEvent / BusinessEvent
            │
持久层  ────  TsdbRepository (泛型接口)
            │
驱动层  ────  TsdbClient (Lindorm / TDengine 实现)
            │
监控层  ────  TsdbMetrics（写入耗时、失败率、连接池）
```


## 收获（Result）

新框架上线后接入新表的成本从 0.5 天降到 1 小时，重连/序列化等公共能力收敛后再没出过类似问题；后续 APM、监控、业务事件三个模块统一接入，重复代码减少约 70%。
