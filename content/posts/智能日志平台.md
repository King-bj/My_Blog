# 智能日志平台：把异常日志主动推到工程师面前

## 背景（Situation）

生产环境涉及上百个微服务，没有完善的可观测体系问题定位就只能靠肉眼看日志，效率极低。

## 目标（Task）

我主导监控与日志体系的设计与落地，目标是让任何线上问题都能在分钟级被发现并定位。

## 行动（Action）

### 背景

智能日志产品能够实现离散日志数据的统一采集、处理、检索、模式识别和可视化分析。从运维侧、运营侧、安全侧等不同领域输出业务价值。

### 功能

日志统一管理：实现对所有设备、业务等离散日志的一站式采集、处理、存储、归档以及查询。

智能化运维：对指标数据进行智能异常检测，发现业务异常，提升告警准确率。提供应用日志异常检测、单笔业务端到端分析手段等。

数字化运营：对业务系统进行综合分析，包括业务总量、成功次数、失败次数、成功率，以及未来业务趋势及业务统计报表等。

### 技术栈

SpringBoot  基础框架

SpringBoot Gateway 网关

Feign 服务调用

[MyBatis-Plus](https://baomidou.com/) 数据库操作

Nacos 配置中心

Mysql 结构数据存储

ElasticSearch 采集/告警数据存储

Flume agent采集

Redis 缓存

Kafk 消息队列

Spark 日志解析

Docker 镜像管理

### 职责

负责日志服务整体架构的设计规划，基于原始版本进行了架构升级改造。完成了java服务升级为spring cloud微服务架构，支持容器化部署，中间件版本升级适配等工作。

- 性能优化
  - 基于spark + drools进行数据分析，优化spakr任务解析逻辑，由资源占用1c1g的spark任务每秒处理日志数约为300条/s 优化为10000条/s，并可以根据资源数进行kafka->es的多种组合式扩容
- 功能开发
  - 基于ssh，实现了agent的远程安装及配置下发
  - 基于flume，实现各类源日志的采集
  - 基于drools，根据页面配置数据规则，自动生成drools脚本,实现动态清洗日志数据
  - 基于开源大模型chatglm/通义千问，实现日志的语义分析功能
- 产品适配
  - 基于flume，在原有采集方案上修改k8s容器的采集方案，基于sidecar方式部署agent,不侵入其它系统采集，实时日志可达每秒1000条
  - 适配容器化环境，支持k8s安装，支持arm64和x86类型的服务器
  - 基于 mybatis-plus, 兼容mysql,db,kingbase
  - 基于bboss框架，es兼容es7,8,opensearch。升级后架构支持日均采集30G日志，总日志保留半年稳定运行半年基本无异常。
