# Kubernetes 控制机制（声明式 + Reconcile）设计解读

## 背景（Situation）

团队成员对 K8s 只停留在 `kubectl apply` 的层面，遇到调度异常、Operator 行为不一致时无从下手。

## 目标（Task）

把 K8s 的核心控制机制——声明式 API + Controller Loop——讲清楚，作为内部技术分享材料。

## 行动（Action）

**控制逻辑应该只依赖于当前状态**。这一点我理解同样来源于API设计理念里的**尽量避免让操作机制依赖于全局状态**，通过对当前状态的判断进行修正，保证在经常出现局部错误的分布式系统中，系统最终能达到声明的状态。

**假设任何错误的可能，并做容错处理**。

## 收获（Result）

分享之后团队成员能独立看懂 Controller 源码，遇到调度问题也能直接进入 Reconcile 链路定位。
